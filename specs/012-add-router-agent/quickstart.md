## Overview

This guide details developer setup, manual verification steps, API cURL tests, and automated testing instructions for validating the Router Agent feature (`012-add-router-agent`).

---

## Prerequisites & Environment Setup

1. Ensure the PostgreSQL database is running.
2. Apply Alembic migrations to update the database schema:
   ```bash
   cd backend
   alembic upgrade head
   ```
3. Start backend API server:
   ```bash
   cd backend
   uvicorn main:app --reload --port 8000
   ```
4. Start frontend web app:
   ```bash
   cd frontend
   npm run dev
   ```

## Testing Scenarios

### Scenario 1: Creating a Router Agent via UI
1. Open the web app at `http://localhost:5173`.
2. Navigate to **Painel de Agentes** -> Click **Novo Agente**.
3. Verify that the creation modal presents options:
   - **Agente Padrão** (Default agent option)
   - **Agente Roteador** (Router agent option)
4. Select **Agente Roteador**.
5. Fill in details:
   - Name: `Roteador de Teste`
   - Prompt do Roteador: `Se a mensagem for sobre agendamento, encaminhe para Agendamento. Se for dúvida, encaminhe para Suporte.`
   - Fallback Agent: Select `Agente de Suporte`.
   - Destinations: Add `Agente de Agendamento` and `Agente de Suporte`.
6. Click **Salvar Agente**.
7. Confirm that `Roteador de Teste` appears in the list with a distinct **"Roteador"** badge.

### Scenario 2: API Testing via cURL

#### Step 1: Create Router Agent via API
```bash
curl -X POST http://localhost:8000/agents \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "name": "Roteador API Teste",
    "description": "Teste de Roteamento via API",
    "agent_type": "router",
    "router_prompt": "Se a mensagem contiver a palavra agendar ou consulta -> Agendamento. Caso contrário -> Suporte",
    "fallback_agent_id": 1,
    "destinations": [
      { "destination_agent_id": 1, "routing_instruction": "Suporte geral" },
      { "destination_agent_id": 2, "routing_instruction": "Agendamento" }
    ]
  }'
```

#### Step 2: Execute Message through Router Agent
```bash
curl -X POST http://localhost:8000/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "agent_id": 10,
    "message": "Quero agendar uma consulta para amanhã às 14h",
    "session_id": "test_session_router_1"
  }'
```

#### Step 3: Verify Response Metadata
Check that the response contains `debug.routing` object showing `selected_agent_id: 2`, `is_fallback: false`, and that the response content was generated by the Scheduling Agent.

## Automated Unit & Integration Tests

Run the dedicated router test suite:
```bash
cd backend
pytest tests/test_router_agent.py -v
```

Verification Checklist:
- [x] Create standard agent (type `"standard"`) succeeds.
- [x] Create router agent (type `"router"`) with valid prompt & destinations succeeds.
- [x] Create router agent with 0 destinations fails validation (400 Bad Request).
- [x] Routing message evaluates prompt and delegates to correct destination agent.
- [x] Routing unclassified message triggers fallback agent.
- [x] Routing to inactive destination agent redirects to fallback agent.
- [x] Conversation history is completely transferred to destination agent.
